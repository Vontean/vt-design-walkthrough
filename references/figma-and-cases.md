# Figma 解读与用例

## 文件清单

1. 用 Figma 连接器读取文件/Page 清单。节点工具需要 file key 和 node ID；从用户链接提取，使用工具当时的参数定义。
2. 区分目标交互稿、参考素材、旧版本和组件库。用户范围不明确时先从主交付页面推进，记录排除依据；确有多套冲突交付再询问。
3. 保存有序 Page 清单和 module_order（按功能接近程度排序）；对当前 Page 读取 frame、原型连线、交互注释、状态分支和关键组件属性。大型返回先取节点树，再按相关区域读取，减少重复全量文本。

完成：能够定位目标 Page、页面入口、跨页目的地及规则来源。

## 转为验收用例

按功能建立 case，分别覆盖：
- 入口和返回路径；触发点是否可发现，点击区域、反馈和目标正确。
- 主流程、取消和失败恢复；状态变化后是否保留正确内容。
- 设计里明确给出的加载、空、成功、错误、禁用、权限及账号/设备差异。
- 布局层级、字号字重、图标、颜色、对齐间距、截断和滚动固定区域。
- 明确给出的动效方向、时长、曲线、遮罩和层级。

只检查本次设计和目标功能要求的边界，不自动增加整个产品的通用测试矩阵。一个用例可以覆盖紧密关联的小步骤，独立分支另列。expected 写可观察行为，区分明确设计要求与模型推断。把所需数据写入 preconditions。

把要求写入当前 Page.requirements，case_ids 关联本 Page 的用例；平台不同分别关联。完成：每条需求能追到至少一个用例；每个用例有可执行步骤和可判定预期。

## 比较依据

真实 Figma frame、属性和交互注释共同形成依据。使用节点截图工具导出原始像素，保留精确节点链接；工具返回下载资源时仅按允许方式保存原资源。不要用生成图替代稿件。

对尺寸先定位实际手机内容边界，比较同一逻辑宽度；镜像窗口缩放和 Mac 外围不是设计尺寸。可见图形与组件点击区域分别检查。字体大小/字重等关键判断读取真实属性，不只凭缩略图。图片导出受缩放影响时说明比较方法。

存在新旧规则冲突：记录规则来源，明确需要确认或用户指定的新规则。缺少动效规格时只反馈已观察的体验及建议，不能虚构 Figma 中存在的曲线或时长。
