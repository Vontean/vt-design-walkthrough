# Confluence 写入与核验

## 准备

1. 使用用户指定的 Atlassian 插件/连接器读取目标最新内容、编辑版本与可用格式指南。识别目标表格、原生状态/日期/媒体节点及其外层宏。只有编辑草稿时读取草稿版本。
2. 读取 user-profile.json 与 confluence.json，并核对现有模板。个人配置是署名、署名颜色和尺寸的唯一来源；模板配置管理列角色、标签与保存模式。当前用户指示优先，实际调整保存到本地配置副本。
3. 把实际列顺序与 confluence.columns、column_roles 对照；现有 HTML adapter 仅支持已声明的九列角色顺序，其他格式或顺序需明确适配后再写。回读当前列宽、原有内容及用户修改。保留表头、列宽、外层宏、非本次行和不负责字段；表格脚本生成的是新增行片段，不替代整页。
4. 检查本地所有拟写入项 review=confirmed、publish=true。每条有问题/上下文图、设计依据图及明确性质；用户不反馈的项不上传。

完成：模板、写入范围和授权明确；本地稿已通过校验。

## 上传与行生成

1. 针对图片计算 SHA256，查询 attachments.json；已有目标附件复用，否则用当前连接器附件工具上传。若工具提供短期上传命令，按原指令执行并检查返回值，仅记录永久 file_id/collection/filename。
2. 收集附件映射后执行 build-confluence-table.py --help；传入运行目录、--confluence 模板路径、--user-profile 个人配置路径、当地日期和附件映射。生成的 HTML 原生节点仅用于支持这种格式的连接器；其他格式按当时的官方工具契约适配。
3. 原生状态来自 confluence.issue_status；issue_type 依据 confluence.type_guidance，从允许的 issue_types 中选择；平台填写真实平台，模块顺序来自 run.module_order。coverage_request 正文明确是覆盖请求而非已确认缺陷。
4. column_roles 的 problem 列含标题、触发条件/实际表现和红框图；discussion 列含 user-profile.author、原生日期、反馈、用户审阅说明、Figma 精确链接及蓝框图。kind=needs_confirmation/design_change/coverage_request 明确标注性质。
5. 原生日期来自运行当地日期，不固定历史日期。媒体引用真实附件 ID；主图使用 manifest 中的完整 problem_image/design_image，预览尺寸来自 user-profile，保留完整附件供放大查看。局部放大图可用于本地复核，不能替换表格主图。模块切换插入一个空行，不在同一模块重复插空。

完成：所有拟写入行和真实附件对应，表格片段准备好；无临时凭据写入日志。

## 试写、批量与未知结果

新模板/节点格式有变化：先写一个代表条目，回读并查看 UI，请用户确认格式后再批量。已确认模板结构未变化：直接批量。

带最新版本/快照保护执行最小范围编辑。每批建议按一组功能或连接器可接受大小拆分；不把上次成功体积当作当前服务限制。写前保存内容快照，写后回读该批编号/内容/附件；检查点记录已验证的条目。

超时或 snapshot_stale 等响应不能单凭错误判断未生效：读取最新内容，按稳定编号及媒体 ID 核对。已经生效则记录成功；未生效且目标仍符合预期才重试；并发变化则重新构造最小改动。重复失败或无法确认目标时保留本地结果，请用户解除具体阻塞。

完成：每批条目均被确认已写入，或明确尚未写入；不会凭未确认响应重复插入。

## 验证与交付

保存服务器回读快照，解析为 writeback.json；执行 validate-delivery.py --writeback。核对编号无重复、条目数量、模块顺序和间隔、标签、平台、署名、日期、Figma 链接、图片数及预览尺寸。比较写前后内容，确认其他行和不管理字段保持一致。

最后用浏览器检查首条、模块边界、末条和特殊类型，查看真实图片加载、尺寸与可读性；将结果写入 visual_verified。confluence.save_mode 为草稿时仅保存草稿，报告由用户点击更新发布；有明确发布授权才发布。交付目标链接、数量分类、验证报告和未完成项。
